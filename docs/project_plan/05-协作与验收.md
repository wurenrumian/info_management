# 05 协作与验收

## 1. 协作规则

1. 分支：`main` / `develop` / `feature/*`
2. PR 必需：变更说明、接口影响、DDL影响、测试证据
3. 契约优先：先改文档，再改代码
4. `Phase 1` 的公共能力变更必须先过文档审查再开发
5. `Phase 2/3` 不得绕过 `Phase 1` 直接定义新的公共身份或权限语义

## 2. 变更流程

1. API 改动：先改 `03-API规范.md`
2. Phase 1 结构化改动：同步改 `03-openapi-phase1.yaml`
3. DDL 改动：同步改 `04-数据库设计-DDL.md`
4. 若改动影响联调流程或验收口径：同步改 `02-阶段开发计划.md` 与本文件

## 3. 测试要求

最低覆盖：
1. 鉴权与权限隔离
2. 班级/年级数据范围控制
3. 导入导出稳定性
4. 管理日志完整性

Phase 1 最低测试清单：
1. 微信登录、绑定、刷新、退出
2. 当前用户读取与允许字段更新
3. 用户、班级、管理员查询的范围隔离
4. 用户创建、更新、班级成员批量绑定
5. 用户导入、班级导入、作业状态查询、错误报告生成
6. 用户导出
7. 管理日志写入与按条件查询

## 4. 里程碑（10周示例）

1. 周1-2：Phase 1
2. 周3-6：Phase 2 并行
3. 周5-8：Phase 3 前端并行
4. 周9：联调与压测
5. 周10：试运行与交付

### Phase 1 周级拆分建议

1. 第1周前半
- 冻结 API、DDL、权限口径
- 完成迁移脚本和基础项目骨架

2. 第1周后半
- 完成鉴权、当前用户、用户/班级基础查询

3. 第2周前半
- 完成管理员管理、范围控制、成员绑定

4. 第2周后半
- 完成导入导出、审计日志、回归测试与联调

## 5. 交付清单

1. 可部署后端与小程序
2. API 文档与 OpenAPI 文件
3. 数据库设计与迁移脚本
4. 测试报告与用户手册
5. 答辩演示材料

## 6. Phase 1 联调准入条件

1. OpenAPI 与实现接口路径一致。
2. 所有 Phase 1 写接口都明确操作者权限。
3. 导入模板和错误报告格式已固定。
4. 至少准备一个学生账号、一个普通管理员账号、一个超级管理员账号用于联调。

## 7. Phase 1 验收清单

1. 学生可完成登录、绑定并读取本人信息。
2. 管理员可完成用户、班级、管理员的基础维护。
3. 非授权用户无法读取或修改越权数据。
4. 用户导入和班级导入可生成作业并反馈成功/失败统计。
5. 错误报告可定位到失败行和失败原因。
6. 用户导出可按筛选条件返回结果。
7. 关键管理写操作均可在日志中查询到。
